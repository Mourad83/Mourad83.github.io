DATA PIPELINE 360

Automated Analytics Pipeline

DATA PIPELINE 360 est un projet de bout en bout qui montre comment transformer des fichiers sources bruts en un reporting Power BI structuré, fiable et exploitable.

Le projet couvre toute la chaîne : réception des fichiers, contrôle qualité, traitement Python, stockage SQLite, création de vues SQL, modélisation Power BI et visualisation des KPI.

Objectif du projet

Construire une chaîne analytique complète, automatisée et maintenable.

Contexte

Les entreprises reçoivent souvent plusieurs fichiers métiers dans des formats différents. Sans pipeline clair, les contrôles sont manuels, les erreurs se multiplient et le reporting manque de fiabilité.

Réponse apportée

Ce projet met en place un pipeline qui centralise les sources, contrôle leur qualité, crée des vues analytiques SQL et alimente un rapport Power BI multi-pages orienté pilotage.

Architecture du pipeline

Vue simplifiée des blocs techniques, de la réception des fichiers jusqu’au reporting final.

01
Réception des fichiers sources
Dépôt des fichiers bruts dans le dossier landing : CSV Sales, Excel Master Data, CSV Targets.
02
Traitement Python
Lecture des fichiers, validation des colonnes, contrôle des types, détection des doublons et des valeurs invalides.
03
Contrôle qualité
Création de l’historique de traitement avec statut SUCCESS / FAILED / ERROR et détail des anomalies détectées.
04
Chargement SQLite
Insertion des données valides dans les tables du modèle et conservation de l’historique de chargement.
05
Vues SQL analytiques
Création des vues métiers pour les ventes, produits, clients, objectifs et qualité des données.
06
Power BI Reporting
Modélisation, mesures DAX, navigation entre pages, filtres et visualisations interactives.

Dessin du flux : Sources → Python → Data Quality → SQLite / SQL Views → Power BI Model → Dashboard final.

Défis techniques

Trois problèmes concrets traités pendant la construction du pipeline.

1. Fiabiliser les fichiers entrants

Problème : les fichiers peuvent contenir des colonnes manquantes, doublons, dates invalides, quantités négatives ou références inconnues.

Solution : mise en place de contrôles Python avant chargement : structure, valeurs nulles, doublons, types, cohérence des montants et clés de référence.

Résultat : les fichiers non conformes sont rejetés avant leur intégration dans la base et les anomalies sont tracées.

2. Éviter les doubles chargements

Problème : un même fichier ne doit pas être chargé plusieurs fois lors des exécutions successives du pipeline.

Solution : utilisation de la table File_History et des statuts SUCCESS / FAILED / ERROR pour suivre chaque traitement.

Résultat : les fichiers déjà chargés avec succès sont identifiés et le traitement devient traçable.

3. Préparer les données pour l’analyse

Problème : les données transactionnelles brutes ne sont pas directement adaptées au reporting et aux analyses récurrentes.

Solution : création d’un modèle SQLite avec tables de faits et dimensions, puis de vues SQL dédiées aux ventes, clients, produits, objectifs et à la Data Quality.

Résultat : Power BI consomme une couche analytique structurée et réutilisable.
